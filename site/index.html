The OCI CLI,

boci is a drop-in replacement for Oracle's oci CLI, built on Bun. Same commands, same flags, same output, with a start-up measured 32× faster. Swap oci for boci and your scripts keep working.

Get started View on GitHub 
$ alias oci=boci   # that's the whole migration
$ oci os ns get
$ git clone https://github.com/neves/boci && cd boci
$ bun install && bun run build   # → dist/boci

Drop-in

Same commands. Same flags. Same bytes.

boci aims for 1:1 parity with the oci CLI: every service, command and flag, the same JSON on stdout, the same error shape on stderr, the same exit codes, and the same ~/.oci/config, oci_cli_rc and OCI_CLI_* behaviour. Anything that can't match yet is listed as a known divergence instead of failing silently.

~ zsh
$ time oci os ns get
{
  "data": "axaxnpcrorw5"
}
oci      0.49s

$ time boci os ns get
{
  "data": "axaxnpcrorw5"
}
boci     goal: under 0.1s · in progress

How it works

Generated from oci itself, verified against oci itself.

Most of the oci CLI is generated from the OCI SDK. boci doesn't rewrite 9,000 commands by hand. It reads them out of the real CLI and runs them all with one small engine.

Extract

An extractor loads the pinned oci CLI and records every service, command, flag, default and HTTP operation as data.

9,372 commands across 175 services

Execute

One generic engine handles config, request signing, pagination, --query and output for every generated command. Hand-written code covers the rest, like multipart uploads.

8,184 generated · 1,188 hand-written

Verify

Parity tests compare boci with the real oci: the request it sends, stdout, stderr and exit code. Responses are recorded once, so the suite runs offline in seconds.

1:1 or it's a recorded divergence

Install

Get boci

There's no release yet. Once commands work, boci will ship as a single binary for Linux and macOS (x64 and arm64). Until then you can build it from source with Bun 1.4.5 or newer.

build from source 
$ git clone https://github.com/neves/boci
$ cd boci && bun install
$ bun run build          # → dist/boci
$ bun run status         # what works, what's missing
$ bun test               # offline parity suite
use it as oci (once commands land) 
# boci reads your existing ~/.oci/config
$ boci os ns get --profile my-profile

# or make it the default, scripts unchanged
$ alias oci=boci

# hand unimplemented commands to the real oci
$ export BOCI_FALLBACK=oci

FAQ

Questions

Is this an official Oracle project?

No. boci is an independent open-source project and isn't affiliated with or endorsed by Oracle. It talks to the same public OCI APIs the official CLI uses.

Will my scripts break?

That's the point of the parity tests: the same invocation should produce the same stdout, stderr error object and exit code. Commands boci doesn't support yet fail with a clear message, or, with BOCI_FALLBACK=oci, are handed to the real oci.

Why Bun?

Bun compiles TypeScript into one self-contained executable that starts in milliseconds, with fast built-in crypto, HTTP and JSON. boci also skips the OCI SDK and signs requests itself, so there's very little to load.

Why is the binary 106 MB?

Most of it is the Bun runtime embedded in every compiled Bun app. The command data for all 9,372 commands adds only 2.3 MB compressed. It's still one file, under a quarter of the size of the Python install, with nothing else to set up.

Which oci version does boci match?

oci-cli 3.96.3. Moving to a newer oci release regenerates the command data and shows exactly what changed.
